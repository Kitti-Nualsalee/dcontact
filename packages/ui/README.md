# @d-contact/ui

design token ของ D-Contact — แหล่งความจริงเดียวของสี ตัวอักษร มุมโค้ง เงา และ focus ring
ที่ `apps/workspace` กับ `apps/console` ต้องใช้ร่วมกัน ตาม [ADR-026](../../docs/adr/026-frontend-app-split.md) ข้อ 6

แพ็กเกจนี้ถือ **token เท่านั้น** ไม่มี component, routing, data fetching หรือ live-session authority

## ใช้ยังไง

```ts
// ที่ entry ของแอป โหลดครั้งเดียว
import '@d-contact/ui/tokens.css';
```

```js
// tailwind.config.js ของแต่ละแอป
module.exports = {
  presets: [require('@d-contact/ui/tailwind-preset')],
  content: ['./src/**/*.{ts,tsx,html}'],
};
```

```ts
// เมื่อต้องส่งสีให้ของที่รับ CSS ไม่ได้ เช่น canvas ของ waveform
import { tokens, cssVar } from '@d-contact/ui';

ctx.fillStyle = tokens.partyAgent;        // '#0f766e'
element.style.background = cssVar('surfaceRaised'); // 'var(--dc-surface-raised)'
```

ดู token ทั้งหมดพร้อมตัวอย่างจริงได้ที่ `preview.html` (มี launch config ชื่อ `ui-tokens` พอร์ต 8095)

## กติกา

1. **ห้ามเขียน hex ในโค้ดแอป** ถ้าต้องการสีที่ยังไม่มี ให้เพิ่ม token พร้อมชื่อบทบาท ไม่ใช่หยิบค่าใกล้เคียงมาใช้
2. **ห้ามใช้ palette เดิมของ Tailwind** (`bg-teal-700`, `text-slate-400`) — preset ตัดออกแล้วโดยตั้งใจ
   `text-slate-400` คือคู่สีที่ทำให้ mockup ตก WCAG AA มากที่สุด
3. **สีสองประเภทห้ามปนกัน** — ดูหัวข้อถัดไป
4. รันตัวตรวจก่อน commit ที่แตะ token: `pnpm --filter @d-contact/ui test`

## severity กับ identity

สีในระบบนี้ทำสองหน้าที่ที่ไม่เหมือนกัน และ `mockups/assets/app.css` ไม่ได้แยกไว้:

| | severity | identity |
|---|---|---|
| ตอบคำถาม | "เรื่องนี้หนักแค่ไหน" | "นี่คือใคร/อะไร" |
| ตัวอย่าง | สำเร็จ · ต้องดู · วิกฤต · ข้อมูล | voice · LINE · WhatsApp · กะดึก · ลูกค้า vs เอเจนต์ |
| กติกา | หนึ่งบทบาทหนึ่งตระกูลสี **ยุบได้** | ต้องแยกจากกัน **ห้ามยุบ** |

เขียวของ LINE กับเขียวของ WhatsApp ที่ดูซ้ำกันนั้นถูกแล้ว — ถ้ายุบ ป้ายช่องทางจะแยกไม่ออก
และห้ามหยิบค่าจากกลุ่ม severity มาใช้กับ identity ไม่งั้นป้ายช่องทางสีแดงจะถูกอ่านเป็นการเตือน

ตัวอย่างที่ token แก้ให้: `.ch-voice` (ช่องทาง), `.pri` (ลำดับความสำคัญ) และ `.es-amend` (สถานะผลประเมิน)
เคยใช้คู่สี `#e0e7ff/#4338ca` เดียวกันทั้งที่คนละความหมาย ตอนนี้เป็นสาม token ที่ชี้ค่าเดียวกัน
จึงแยกออกจากกันในอนาคตได้โดยไม่ต้องไล่หาทีละที่

## สิ่งที่เปลี่ยนจาก mockup และเหตุผล

งานนี้คือการทำให้เป็นระบบ ไม่ใช่ออกแบบใหม่ — hue ทุกตัว, มุมโค้ง, เงา และ layout ไม่ถูกแตะ
สิ่งที่เปลี่ยนมีสี่อย่าง:

**1. ยุบตระกูลสีที่ทำงานซ้ำกัน** — เดิมหนึ่งบทบาทมีสองตระกูล

| บทบาท | เดิม | เหลือ |
|---|---|---|
| อันตราย/เกินเกณฑ์ | `red-*` และ `rose-*` | `red-*` |
| หมวดหมู่/AI | `violet-*` และ `purple-*` | `violet-*` |

ทั้งสองคู่ต่างกันด้วยตาแทบไม่ออก แต่ต่างกันตอนแก้ ผลคือจาก 62 hex เหลือ 134 token ที่มีชื่อบทบาท
(จำนวนมากขึ้นเพราะหนึ่งค่าถูกเรียกด้วยหลายชื่อตามหน้าที่ ซึ่งเป็นสิ่งที่ต้องการ)

**2. root font 18px → 16px** — Tailwind ใช้ rem ทั้งหมด root 18px จึงทำให้ระยะห่างทุกค่าพองขึ้น 12.5%
ขณะที่ CSS ของ component เป็น px คงที่ ได้ระบบสองมาตราส่วนที่ไม่ขยับพร้อมกัน
หลักฐาน: ตาราง virtual agents ต้องการความกว้าง 1323px ตั้งแต่จอ 1440px

type scale จึงถูกนิยามเป็นค่าสัมบูรณ์เพื่อให้ **ตัวอักษรออกมาขนาดใกล้เคียงของเดิม** แต่ layout ได้ที่คืนมา
เช่น ตัวหลักในตารางเดิม `text-sm` = 15.75px ตอนนี้ `--dc-text-base` = 14px และ `--dc-text-md` = 16px
scale เหลือ 7 ขั้นหลัก จากเดิม 17 ขนาดกระจัดกระจายตั้งแต่ 9px ถึง 44px

**3. แก้คอนทราสต์ที่ตก WCAG AA** — ตรวจ mockup พบ 55 จาก 559 element บนหน้าเดียวตกเกณฑ์

| ที่ | เดิม | ตอนนี้ |
|---|---|---|
| ป้ายกลาง, สถานะออฟไลน์, วันหยุด | `#64748b` บน `#f1f5f9` = 4.34:1 | `#475569` = 6.15:1 |
| ข้อความรองทั่วไป | `#94a3b8` บนขาว = 2.56:1 (ใช้ 310 จุด) | `--dc-text-muted` `#64748b` = 4.76:1 |
| หัวข้อกลุ่มเมนู | `#d97706` บนขาว = 3.19:1 | `--dc-attention-fg` `#b45309` = 5.0:1 |
| ป้าย NEW/LIVE | `#16a34a` บน `#d6f5e3` = 2.83:1 | `--dc-success-fg` บน `--dc-success-bg` = 4.57:1 |

`#94a3b8` ยังอยู่ในชื่อ `--dc-text-disabled` สำหรับ control ที่กดไม่ได้และไอคอนตกแต่งเท่านั้น

**4. เพิ่ม focus ring** — mockup เดิมมี focus style อยู่ 2 บรรทัดในทั้งไฟล์ (เฉพาะตัวลากแบ่งคอลัมน์)
`tokens.css` ใส่ `:focus-visible` ให้ทุก control ที่กดได้ เพราะเอเจนต์ทำงานด้วยคีย์บอร์ดตลอดกะ

## ช่องว่างที่รู้ตัวและยังไม่แก้

ตัวตรวจพิมพ์สองข้อนี้ทุกครั้งโดยไม่ทำให้ gate แดง เพราะทั้งคู่เป็นค่าที่อนุมัติไว้ใน mockup แล้ว
และการแก้จะเปลี่ยนน้ำหนักภาพของทุก input และทุกตัวบอกสถานะว่าง ซึ่งเกินขอบเขตของงานสกัด token:

- `--dc-border-default` บนพื้นขาว = **1.48:1** (WCAG 1.4.11 ต้องการ 3:1 สำหรับขอบที่ใช้ระบุ control)
- `--dc-neutral-solid` บนพื้นขาว = **2.56:1** (จุดและแถบที่แปลว่า "ไม่มีอะไรเกิดขึ้น")

ทั้งสองข้อต้องให้เจ้าของผลิตภัณฑ์ตัดสิน ไม่ใช่ตัดสินเงียบ ๆ ตอน refactor

## ยังไม่ได้ทำ

- **ยังไม่มีใครใช้แพ็กเกจนี้** — `apps/workspace/src/workspace-app.css` (923 บรรทัด, custom property 0 ตัว, hex 31 ค่า)
  ยังไม่ถูกย้ายมา เพราะไฟล์นั้นกำลังถูกเขียนอยู่ การย้ายต้องทำตอนที่งานฝั่งนั้นนิ่งแล้ว
- **ยังไม่มี component** — ปุ่ม ป้าย ตาราง สถานะช่องทาง ยังอยู่ในแต่ละแอป
- **ยังไม่มีโหมดมืด** — wallboard ใช้ `--dc-surface-inverse` เป็นพื้นเข้มบนธีมสว่าง ไม่ใช่ธีมมืดทั้งระบบ

## โครงไฟล์

```
src/tokens.css            แหล่งความจริงเดียว — แก้ที่นี่ที่เดียว
src/tokens.generated.ts   สร้างอัตโนมัติจาก tokens.css ห้ามแก้ด้วยมือ
src/tailwind-preset.cjs   ทำให้คลาสของ Tailwind ชี้กลับมาที่ token ตัวเดียวกัน
scripts/generate-tokens.mjs
scripts/check-contrast.mjs  ตัวตรวจ WCAG AA (pnpm --filter @d-contact/ui test)
preview.html              แผ่น token พร้อมตัวอย่างจริง
```
