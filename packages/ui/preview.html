D-Contact design tokens

Extracted from mockups/assets/app.css, the Phase 2 visual contract. This page uses tokens for every value; a color that still needs a hex means a token is missing

Surfaces and borders

Ordered by depth, not brightness — cards sit on the page background, wells sit inside cards

Typography

--dc-text-disabled is the only value that must not be used for meaningful text. The old mockup used it in 310 places for times and secondary text.

Severity

One role, one color family. The badges below are real agent statuses that must stay readable all shift

Identity

Channels and shifts are not severity levels. LINE green and WhatsApp green look alike but are different channels, so they must not be merged

Type scale

7 main steps plus 2 steps for large numbers (previously 17 sizes from 9px to 44px), measured at root 16px

Corner radius

Halved from the values extracted from the mockup (D1.4) — pill is for avatars, status dots and counters only

Spacing

One scale on a 4px base; components must not use spacing outside these 10 steps

Standard heights (density)

Named by role so they can be overridden under [data-density] in the future — D1 has a single set and it is deliberately below the 44px touch target
