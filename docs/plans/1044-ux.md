## 1. ผู้ใช้และงานที่ต้องสำเร็จ

- **เอเจนต์** (`apps/workspace`, ตาราง "ผู้ใช้และบริบท" ใน `ui-principles.md`) คุยหลายห้องพร้อมกันทั้งกะด้วยคีย์บอร์ด
  ต้องเห็นทันทีว่าห้องไหนลูกค้ารอคำตอบ รับแชทใหม่ได้โดยไม่หลุดจากห้องที่พิมพ์อยู่ และปิดงานด้วยผล/โน้ตแบบเดียวกับ Voice
- **ลูกค้าบนเว็บ tenant** (ไม่ระบุตัว) เปิด widget พิมพ์ได้ทันที รู้เสมอว่ากำลังรอ คุยอยู่ หรือจบแล้ว และไม่เสียข้อความเมื่อเน็ตหลุดหรือรีเฟรช
- **Admin** (`apps/console`) ตั้งค่านาน ๆ ครั้ง ต้องรู้ว่าอะไรยังขาดก่อนเปิดใช้งาน และคัดลอกโค้ดฝังได้ในขั้นเดียว
- **Agent / Supervisor / Admin** อ่านบทสนทนาย้อนหลังตามสิทธิ์เดิมของ #859/#986 จากหน้าประวัติที่มีอยู่

## 2. User flow

### 2.1 ลูกค้า (widget)

1. หน้าเว็บโหลด `widget.js` → ตรวจ origin + สถานะ widget
   - origin ไม่อยู่ใน allowlist หรือ widget ปิด → **ไม่แสดงปุ่มลอยเลย** (ไม่บอกเหตุกับคนทั่วไป) และ log ฝั่ง server
2. ปุ่มลอย "แชทกับเรา" มุมขวาล่าง → กดเปิดหน้าต่าง 360×560 focus ไปที่ช่องพิมพ์
   - ไม่มี Agent ออนไลน์ในคิว → หน้าต่างแสดง "ตอนนี้ไม่มีเจ้าหน้าที่ออนไลน์" ช่องพิมพ์ disabled ปุ่ม "ตรวจอีกครั้ง" (state 11)
3. เห็นข้อความต้อนรับ (ภาษาตาม browser) → พิมพ์ข้อความแรก Enter → สร้างห้อง เข้าคิว แถบ "กำลังหาเจ้าหน้าที่" (state 4) พิมพ์เพิ่มได้
   - ระหว่างรอ Agent ออนไลน์คนสุดท้ายออก → ห้องยังรอในคิว (ไม่ตัดลูกค้า) จนกว่าลูกค้าปิดเอง ตามข้อ 4 ของ issue
4. Agent รับ → ข้อความระบบ "เจ้าหน้าที่เข้าร่วมแชท" → คุยโต้ตอบ (state 5)
   - ส่งไม่สำเร็จ → ข้อความค้างพร้อม "ส่งอีกครั้ง" (state 6) ส่งซ้ำใช้ `clientMessageId` เดิม (ADR-024)
   - เน็ตหลุด → แถบ "กำลังเชื่อมต่อใหม่" ร่างยังอยู่ ปุ่มส่งปิด (state 7) กลับมาแล้วดึงข้อความที่พลาด
   - รีเฟรช/ย่อหน้าต่าง → กลับเข้าห้องเดิมพร้อมข้อความเดิมถ้าห้องยังไม่ปิด ย่ออยู่แล้วมีข้อความใหม่ → ตัวนับบนปุ่มลอย (state 2)
5. จบได้สามทาง ทุกทางแสดงข้อความระบบ + ปุ่ม "เริ่มแชทใหม่" แทนช่องพิมพ์
   - ลูกค้ากด "จบแชท" → ยืนยันในหน้าต่าง (sheet, state 8) → "คุยต่อ" ย้อนกลับได้
   - Agent จบแชท (state 9)
   - ลูกค้าเงียบเกินเวลาที่ตั้ง (state 10)
6. Admin ปิด widget ระหว่างหน้าต่างเปิด → ห้องที่คุยอยู่คุยต่อจนจบ (ดูข้อ 8 Q6); หน้าต่างที่ยังไม่มีห้องแสดง "แชทปิดให้บริการชั่วคราว" (state 12)

### 2.2 เอเจนต์ (Workspace)

1. Ready → แชทใหม่เด้งเป็น **การ์ด offer บนสุดของรายการงานซ้าย** (ไม่ใช่ modal) มีเวลานับถอยหลัง ปุ่ม "รับแชท" ประกาศผ่าน `aria-live="polite"` ไม่ย้าย focus
2. กด "รับแชท" → ห้องใหม่เข้ารายการ **ถูกเลือกเป็นห้องปัจจุบัน** focus ไปช่องพิมพ์ของห้องนั้น ร่างของห้องเดิมเก็บไว้
   - offer หมดเวลา → การ์ดหายและแสดงบรรทัด "หมดเวลารับ ระบบส่งให้เจ้าหน้าที่คนถัดไปแล้ว" (ปิดได้) ไม่นับเป็นความผิด
   - กดรับแต่ offer หมดแล้ว/คนอื่นรับ (409) → toast "แชทนี้ไม่ว่างแล้ว" การ์ดหาย
   - ครบเพดาน → ระบบไม่ส่ง offer หัวรายการบอก "ครบ 3 ห้อง" TopBar แสดง "แชท 3/3"
3. คุยในห้อง: Enter ส่ง, Shift+Enter ขึ้นบรรทัด, จำกัด 2,000 ตัวอักษร ส่งล้ม → "ลองส่งอีกครั้ง"/"ลบ"
4. ข้อความเข้าห้องที่ไม่ได้เปิด → ตัวนับยังไม่อ่าน + preview ตัวหนา + "รอ m:ss" (เวลาตั้งแต่ข้อความลูกค้าที่ยังไม่ตอบ) ลำดับรายการไม่เปลี่ยน
5. ผูกลูกค้า: แท็บ "Customer 360" ของห้อง = `WorkCustomerPanel` เดิม หรือปล่อย unlinked
6. จบ: Agent กด "จบแชท" → ยืนยัน inline ในหัวห้อง ("จบแชทนี้?" [จบแชท] [ยังไม่จบ]) / ลูกค้าออก / ระบบปิดเพราะเงียบ
   → ห้องเป็น "รอบันทึกผล" ช่องพิมพ์ถูกแทนด้วยแถบเหตุผล + "ไปบันทึกผล" ฟอร์มสรุปผลเดิมในแผงงานขวา
   - ห้องที่รอบันทึกผลยังนับในเพดาน (ตรงกับ ACW ของ Voice)
7. บันทึกผล → toast "บันทึกผลแชท #E5F6 แล้ว" ห้องย้ายไปแท็บ "ปิดแล้ว" focus ไปห้องถัดไปในรายการ (หรือรายการถ้าไม่มี)
   - ล้ม/ไม่ทราบผล → ใช้ข้อความ `wrapup.unknown`/`wrapupFailed` เดิม ฟอร์มไม่ล้าง
8. เปลี่ยนเป็น Not Ready/ออกจากระบบขณะยังมีห้องค้าง → ไม่อนุญาต แถบเตือนบอกจำนวนห้องที่ต้องปิดก่อน (issue ข้อ 7; ดู Q3)
9. เชื่อมต่อหลุด → แถบเตือนบนสุด, ปุ่มส่ง disabled, ร่างไม่หาย, ห้องไม่ remount เมื่อกลับมาดึงข้อความที่พลาดแล้วล้างแถบเอง

### 2.3 Admin (Console ตั้งค่า)

1. การเชื่อมต่อ → ช่องทางลูกค้า → Web Chat
2. ครั้งแรก: สถานะ "ยังไม่ได้ตั้งค่า" + คำแนะนำ ค่าเริ่มต้น 3 ห้อง / 10 นาที ปุ่ม "บันทึกและสร้างโค้ดฝัง"
3. เลือกคิว, เพิ่มโดเมน (ตรวจรูป origin ตอนกดเพิ่ม), ข้อความต้อนรับ TH/EN, เพดาน, เวลาเงียบ, สวิตช์เปิดใช้งาน → "บันทึก" (ปุ่มหลักเดียว)
   - เปิดสวิตช์แต่ยังไม่มีคิวหรือโดเมน → บันทึกไม่ผ่าน error ใต้ field + เช็กลิสต์ "ต้องมีก่อนเปิดใช้งาน" พร้อมลิงก์ไปที่ช่อง
   - server ล้ม → แถบ error บนสุด ค่าที่กรอกยังอยู่ ปุ่ม "ลองบันทึกอีกครั้ง"
   - บันทึกได้ → toast "บันทึกการตั้งค่า Web Chat แล้ว"
4. คัดลอกโค้ดฝัง → ปุ่มเปลี่ยนเป็น "คัดลอกแล้ว" 2 วินาที (pattern เดียวกับ dphone-embedding)
5. Supervisor เปิดได้แบบอ่านอย่างเดียว (ตาม dphone-embedding) role อื่นเห็นหน้า "ไม่มีสิทธิ์"

### 2.4 ประวัติ

1. หน้าเดิม `team-history` / `agent-history` มีคอลัมน์ "ช่องทาง" (สาย/แชท) และตัวกรองช่องทางแบบ segmented ข้างช่วงเวลา
2. กด "เปิด" ที่งานแชท → รายละเอียด: บทสนทนาอ่านอย่างเดียวซ้าย, ผลที่บันทึกขวา ("กลับรายการ" คืน filter เดิมจาก URL)
3. ไม่มีสิทธิ์/ไม่พบ → ข้อความ `notFound` เดิม (ไม่แยกว่าไม่มีหรือไม่มีสิทธิ์)

### 3.2 Widget (นอก design system ของแอป)

- vanilla TS + Shadow DOM (`mode: 'open'`) เพื่อไม่ชน CSS ของเว็บ tenant; ค่าสี/ระยะ **generate จาก `packages/ui/src/tokens.css` ตอน build** ใส่ใต้ `:host` ไม่คัดลอก hex ด้วยมือ
- font: system stack (`system-ui, -apple-system, 'Segoe UI', 'Noto Sans Thai', 'Leelawadee UI', sans-serif`) ไม่โหลด font ภายนอกบนเว็บ tenant
- โครง: ปุ่มลอย (pill 56px, "แชทกับเรา" + ไอคอน) → หน้าต่าง 360×560 (`role="dialog"`, ไม่ modal ต่อหน้าเว็บ): หัว (`--dc-surface-brand`, ชื่อ tenant, สถานะเป็นข้อความ, "จบแชท", ย่อ) / แถบสถานะ / รายการข้อความ (`role="log"`) / ช่องพิมพ์ + ปุ่มส่ง 40px

## 5. คีย์บอร์ดและ focus

Workspace

- ลำดับ tab: TopBar → การ์ด offer ("รับแชท") → รายการงาน (หนึ่ง tab stop, ↑/↓ เลือกแถว, Enter เปิด) → หัวห้อง ("จบแชท") → แท็บ main → รายการข้อความ (`tabindex=0` เพื่อเลื่อนด้วยลูกศร/PageUp) → ช่องพิมพ์ → "ส่ง" → แผงงาน → แถบเครื่องมือ
- ช่องพิมพ์: Enter ส่ง, Shift+Enter ขึ้นบรรทัด, **ไม่ส่งระหว่าง IME composition** (`isComposing`) เกิน 2,000 → Enter ไม่ส่งและอ่าน error
- shortcut ใหม่ (ทำงานแม้ focus อยู่ในช่องพิมพ์ เพราะใช้ Alt): `Alt+↑` / `Alt+↓` ห้องก่อน/ถัดไป, `Alt+Shift+A` รับ offer ล่าสุด (Q2) แสดงใน `title`/คำอธิบายของปุ่ม
- offer เข้า: ไม่ย้าย focus, ประกาศ polite ครั้งเดียว "แชทใหม่จาก ผู้เยี่ยมชม #G7H8 รับภายใน 20 วินาที" ไม่ประกาศทุกวินาที (`role="timer"` ไม่ live)
- กดรับ: focus ไปช่องพิมพ์ของห้องใหม่; สลับห้อง: focus ไปช่องพิมพ์ของห้องนั้น ร่างแต่ละห้องเก็บใน state ต่อ `conversationId` (รอดการสลับห้องและ reconnect ไม่ต้องรอดการรีโหลดหน้า)
- ยืนยันจบแชท: focus ที่ "จบแชท", Esc/"ยังไม่จบ" คืน focus ไปปุ่ม "จบแชท" เดิม; ยืนยันแล้ว focus ไป "ไปบันทึกผล"
- "ไปบันทึกผล": เปิดแผงงานแท็บสรุปผลและ focus ตัวเลือกผลแรก บันทึกแล้ว focus ไปแถวห้องถัดไป
- ข้อความเข้าในห้องปัจจุบัน: `role="log"` อ่านข้อความใหม่แบบ polite; ห้องอื่นไม่ประกาศรายข้อความ (ตัวนับใน accessible name ของแถวพอ)

Widget

- ปุ่มลอยกด Enter/Space เปิด → focus ช่องพิมพ์; Esc หรือปุ่มย่อ → ย่อ focus กลับปุ่มลอย (ไม่จบแชท)
- ลำดับ tab: "จบแชท" → ย่อ → รายการข้อความ → ช่องพิมพ์ → ส่ง ("ส่งอีกครั้ง"/"เริ่มแชทใหม่" อยู่ในลำดับตามตำแหน่ง)
- sheet ยืนยันจบ: focus "จบแชท" (ปุ่มแรก), Tab วนใน sheet, Esc = "คุยต่อ" คืน focus ไป "จบแชท" ในหัว
- `prefers-reduced-motion` ปิด spinner/animation

Console: ลำดับตามการอ่าน การ์ดซ้ายบนลงล่าง → คอลัมน์ขวา, "ไปที่ช่องนี้" ย้าย focus ไป field ที่ขาด, เพิ่มโดเมนแล้ว focus กลับช่องเพิ่ม, ลบแล้ว focus ไปแถวถัดไป (หรือช่องเพิ่ม)
บันทึกล้มที่ field → focus field แรกที่ผิด

## 8. คำถามที่ต้องตัดสิน (เรียงจากผลกระทบมากไปน้อย)

1. **ห้องที่รอบันทึกผลนับในเพดานหรือไม่**
   A) นับจนบันทึกผล (แนะนำ, mockup ใช้) — ตรงกับ ACW ของ Voice กันงานค้างสะสม
   B) ไม่นับ รับแชทใหม่ได้ทันทีที่ห้องปิด — เร็วกว่าแต่ wrap-up ค้างได้ไม่จำกัด
2. **คีย์ลัดรับ offer และสลับห้อง**
   A) `Alt+Shift+A` รับ, `Alt+↑/↓` สลับห้อง ทำงานแม้อยู่ในช่องพิมพ์ (แนะนำ, mockup ใช้)
   B) ไม่มีคีย์ลัดรอบแรก ใช้ Tab ไปที่การ์ด offer — ไม่ชนคีย์ของ browser/IME แต่ช้ากว่า
3. **Not Ready ระหว่างมีห้องค้าง** (issue ข้อ 7 ให้เปลี่ยนได้เมื่อปิดห้องค้างครบ)
   A) ห้ามจนกว่าปิดครบ แสดงแถบเหตุผล (แนะนำ, mockup ใช้ ตรง issue)
   B) อนุญาต "Not Ready" ที่หยุดเฉพาะ offer ใหม่แต่คุยห้องเดิมต่อ — ใช้จริงสะดวกกว่า แต่เปลี่ยนขอบเขตที่ owner ตัดสินแล้ว
4. **ตำแหน่งเมนูตั้งค่า**
   A) `integrations` → section ใหม่ `channels` "ช่องทางลูกค้า" (แนะนำ, mockup ใช้)
   B) `integrations` → section `embedding` เดิมคู่ dphone (ไม่ต้องเพิ่ม section แต่ปนช่องทางลูกค้ากับเครื่องมือเจ้าหน้าที่)
   C) `routing` → section `configuration` (ใกล้คิว แต่ตั้งค่าโดเมน/โค้ดฝังไม่ใช่ routing)
5. **ชื่อเจ้าหน้าที่ใน widget**
   A) แสดงคำกลาง "เจ้าหน้าที่" (แนะนำ, mockup ใช้) — ไม่เปิดชื่อพนักงานต่อคนนอก ไม่ต้องมีฟิลด์ชื่อเล่น
   B) แสดงชื่อแสดงผลของ Agent — เป็นมิตรกว่า แต่เป็นข้อมูลส่วนบุคคลของพนักงานและต้องมีนโยบาย
6. **ปิด widget ใน Console ระหว่างมีห้องคุยอยู่**
   A) ห้องที่คุยอยู่คุยต่อจนจบ ปุ่มลอยหายจากหน้าใหม่ (แนะนำ, mockup ใช้)
   B) ปิดทุกห้องทันที (ต้อง Dialog ยืนยันที่ระบุจำนวนห้องที่จะถูกตัด)
7. **เตือน Agent ก่อนปิดเพราะเงียบ**
   A) ข้อความระบบในห้องเมื่อเหลือ ≤ 2 นาที (เฉพาะฝั่ง Agent) (แนะนำ, mockup ใช้)
   B) ไม่เตือน ปิดตามเวลาเงียบ — ง่ายกว่าแต่ Agent ไม่รู้ว่าห้องกำลังจะหาย
   (การเตือนฝั่งลูกค้าไม่ทำรอบแรก)
8. **ข้อความประวัติเดิมที่พูดถึง "Voice"**
   A) แก้เป็นข้อความกลาง "งาน (สายและแชท)" ทันทีทุก tenant (แนะนำ) — ข้อความยังถูกเมื่อ flag ปิดเพราะไม่มีงานแชท แต่ tenant เดิมจะเห็นคำเปลี่ยน
   B) สลับข้อความตาม flag — ตรงเงื่อนไข "flag ปิดไม่เห็นอะไรเปลี่ยน" แบบเคร่งครัด แต่มี key สองชุด
   หมายเหตุ: ถ้า owner ถือว่า "ไม่เห็นอะไรเปลี่ยน" รวมข้อความ ให้เลือก B
9. **เสียงแจ้ง offer**
   A) ไม่มีเสียงรอบแรก ใช้การ์ด + aria-live + ตัวนับใน title ของแท็บ browser "(1) Workspace" (แนะนำ, mockup ใช้)
   B) เสียงสั้นหนึ่งครั้งต่อ offer — ช่วยเมื่อ Agent อยู่หน้าต่างอื่น แต่ต้องจัดการ autoplay และอาจชนเสียงของ dphone
10. **ช่วงค่าเวลาเงียบ** 1–60 นาที (แนะนำ, mockup ใช้) หรือ 1–30 นาที
11. **origin แบบ http (ไม่ใช่ https)**
    A) รับเฉพาะ https ยกเว้น `http://localhost` เมื่อ tenant อยู่บน dev (แนะนำ ตามกติกา dphone-embedding) B) รับ http ด้วย
12. **token ใหม่ (เสนอเท่านั้น ไม่ได้เพิ่ม)**: `--dc-chat-bubble-self-border` แทนการใช้ `--dc-brand-200` ตรง ๆ เป็นขอบฟองของ Agent
    A) ใช้ `--dc-brand-200` ไปก่อน (แนะนำ) B) เพิ่ม token ชื่อบทบาทเมื่อมีช่องทางที่สอง
