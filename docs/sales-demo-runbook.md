# Runbook: Demo แรกให้ทีมขาย (ฉบับร่าง)

Owner เลือก 19 พฤศจิกายน 2569: เรานำเสนอเองผ่านแชร์จอจาก dev stack บนเครื่อง ไม่ใช้ UAT
เส้นเรื่องใช้ของที่ merge แล้ว: นำเข้าลูกค้าจาก CSV (#909) → Agent เห็นลูกค้าผ่าน segment ระบบ (#911) →
รับสาย เชื่อมลูกค้า บันทึกผล และดูประวัติ (#796) ใช้เวลาประมาณ 10–15 นาที

Stack นี้เป็นเครื่องมือ Demo ไม่ใช่ acceptance: ฐาน `dcontact_demo` ถูก seed ทีม, identity binding และ
สิทธิ์ segment โดยตรงตามที่ owner อนุมัติ (ดูหัวข้อ "สิ่งที่เตรียมให้ล่วงหน้า")

## เตรียมก่อน Demo ทุกครั้ง

```sh
pnpm infra:up
node scripts/sales-demo-stack.mjs --reset
```

- รอจนขึ้น `SALES_DEMO_STACK_READY` (ประมาณ 1 นาที) `--reset` สร้างฐานใหม่ ลูกค้าและประวัติสายจะว่าง
- ไม่ใส่ `--reset` เมื่อต้องการเก็บข้อมูลรอบซ้อมไว้
- ต้องให้ port 3000, 5173 และ 5174 ว่าง หยุด stack ด้วย Ctrl-C
- ตรวจฝั่ง Agent อัตโนมัติหลังนำเข้า CSV แล้ว (ใช้เสียงจำลอง ไม่ต้องมีไมโครโฟน):

```sh
pnpm --filter @d-contact/workspace exec playwright test --config playwright.sales-demo.config.ts
```

ภาพหน้าจอของรอบล่าสุดอยู่ที่ `apps/workspace/test-results-real/sales-demo/`

## หน้าจอและบัญชี

ใช้ Chrome สองโปรไฟล์ (หรือหน้าต่างปกติกับ Incognito) เพราะ Admin และ Agent ใช้ Keycloak เดียวกัน
บัญชีเป็นของ seed ใน `packages/db/prisma/seed.ts` และ realm dev

| บทบาท | เปิดที่                                              | บัญชี                  |
| ----- | ---------------------------------------------------- | ---------------------- |
| Admin | `http://localhost:5174/?tenant=demo` (Console)       | `admin@demo.local`     |
| Agent | `http://localhost:5173/?tenant=demo` (Workspace)     | `agent1000@demo.local` |

สลับภาษาเป็นไทยด้วยปุ่ม TH มุมขวาบนของทั้งสองหน้าก่อนเริ่ม

## ลำดับการเล่า

### 1. Admin นำเข้าลูกค้า (Console)

1. เมนู **ลูกค้า → นำเข้า CSV** เลือกไฟล์ `examples/sales-demo/customers.csv`
2. ระบบจับคู่คอลัมน์ภาษาไทยให้เอง ชี้ให้เห็นว่าแก้การจับคู่ได้ก่อนส่ง
3. กด **ตรวจไฟล์**: ผ่าน 48 แถว ไม่ผ่าน 2 แถว (เบอร์ผิดหนึ่งแถว ไม่มีชื่อหนึ่งแถว) พร้อมเหตุผลรายแถว
4. กด **นำเข้า 48 แถวที่ผ่าน** แล้วยืนยัน: ผลเป็น "สร้างแล้ว 48"

5. เมนู **ลูกค้า → สิทธิ์ทีมเห็นลูกค้า**: ชี้ว่าทีม Customer Care มีสิทธิ์ "ทำงานกับลูกค้าในสาย" บน "ลูกค้าทั้งหมด"
   (stack เตรียมไว้ให้แล้ว) ถ้าจะโชว์การให้สิทธิ์ ให้ถอนแล้วให้ใหม่ด้วยหน้านี้ก่อนไปขั้นของ Agent

ประเด็นที่ควรพูด: ไฟล์ไม่ถูกเก็บ, ตรวจก่อนสร้างเสมอ, ส่งซ้ำไม่สร้างลูกค้าซ้ำ, ลูกค้าที่นำเข้าไม่ถูกเปิดให้ใครเห็นเองจนกว่า
Admin จะให้สิทธิ์ทีม

### 2. Agent รับสาย (Workspace)

1. กด **ตรวจอุปกรณ์เสียง** (อนุญาตไมโครโฟน) แล้วกด **เปิดรับสาย**
2. โทรเข้าคิว 2000 (ดูหัวข้อ "การโทรเข้า") แผง dphone มุมขวาล่างขึ้น "มีสายเรียกเข้า" กด **รับสาย**
3. ถ้าแผงลูกค้าขอให้ยืนยันก่อน ให้กด **ยืนยันตัวตน** หนึ่งครั้ง
4. ค้นลูกค้าด้วยเบอร์เต็ม `+66895550110` กด **เลือกเชื่อมลูกค้า** แล้ว **ยืนยัน**
5. กด **แก้ชื่อและบริษัท** แก้บริษัท แล้ว **บันทึกลูกค้า**
6. กด **วางสาย** เลือกผล **ลูกค้าได้รับความช่วยเหลือ** เขียนโน้ตสรุป แล้ว **บันทึกผล**
7. กด **เปิดผลในประวัติงาน** เพื่อโชว์ผลและโน้ตที่อ่านกลับจาก server

ประเด็นที่ควรพูด: Agent เห็นเฉพาะลูกค้าที่ทีมได้รับสิทธิ์, ระบบไม่เดาตัวบุคคลให้ Agent ต้องเลือกเอง,
ผลหลังสายบันทึกครั้งเดียวแม้กดซ้ำ

### 3. ทิศทางหน้าจอ Agent Workspace (prototype)

Owner เลือก 19 พฤศจิกายน 2569: โชว์ UI ใหม่เป็น prototype ต่อจาก flow จริง ไม่ปรับหน้าจอจริงก่อน Demo
เปิดไฟล์ `mockups/d-contact-agent-workspace-v3.html` ใน Chrome ได้เลย (ไฟล์เดียว ไม่ต้องมี server)
ที่หน้าต่างกว้างอย่างน้อย 1600px ป้ายมุมซ้ายบนขึ้น "Prototype · ข้อมูลจำลอง" ให้บอกทีมขายตรงนี้ก่อนกดอะไร

1. เลือกงานของ **กมลวรรณ ใจดี** (Voice กำลังสนทนา): ชี้แถบสายด้านบน ลูกค้าตรงกลาง และบันทึกผลด้านขวา
2. กด **Hold** แล้วกดอีกครั้งเพื่อคุยต่อ
3. แท็บ **AI** → **สรุปการสนทนา** → **ใช้ในบันทึก** แล้วกลับแท็บ **Notes** ให้เห็นโน้ตที่แทรกมา
4. กด **Hang up** เลือก Disposition **Resolved** แล้ว **บันทึกและปิดงาน**: งานย้ายออกจาก Open
5. เลือกงานที่ขึ้น Ringing แล้วกด **รับสาย** เพื่อโชว์การรับงานถัดไป และเปลี่ยนตัวกรอง Channel ให้เห็น
   LINE, Facebook, Email
6. กดปุ่ม **คืนข้อมูลตัวอย่างเริ่มต้น** (มุมขวาบน) ก่อน Demo รอบถัดไป

สิ่งที่ prototype มีแต่ระบบจริงยังไม่มี ต้องพูดให้ชัด: หลาย channel, Transfer, AI ผู้ช่วย, บันทึกร่าง,
ประวัติ Interactions ของลูกค้าในหน้าเดียวกัน, รายการ Open/Closed หลายงาน, Teams/Inbox/Analytics
ส่วนที่ทำงานจริงแล้ววันนี้คือ รับสาย, Mute, Hold, Keypad, วางสาย, เชื่อมและแก้ลูกค้า, Disposition และโน้ต

## คำถามที่ทีมขายอาจถามและคำตอบตามจริง

- **Admin ของ tenant ใหม่นำเข้าลูกค้าได้เลยไหม:** ยังไม่ได้ ต้องให้ operator ของเราให้สิทธิ์สร้างลูกค้าก่อน
- **ให้สิทธิ์ทีมเห็นลูกค้าจากหน้าจอได้ไหม:** ได้ ที่ ลูกค้า → สิทธิ์ทีมเห็นลูกค้า เลือกทีมและกลุ่มลูกค้าจากรายการ
  แต่กลุ่มลูกค้ามีแค่ "ลูกค้าทั้งหมด" กับ "ลูกค้า VIP" ยังสร้างกลุ่มเองไม่ได้
- **ค้นลูกค้าด้วยชื่อได้ไหม:** ระหว่างสายค้นได้ด้วยเบอร์สากลเต็มหรืออีเมลเต็มเท่านั้น
- **ระบบจับคู่ลูกค้าจากเบอร์ที่โทรเข้าให้เองไหม:** ยังไม่ทำ Agent ต้องค้นและยืนยันเอง
- **Supervisor, รายงาน, บันทึกเสียง, LINE, โทรออก, สายจากเครือข่ายจริง:** ยังไม่อยู่ใน Demo นี้ มี mockup
  ใน `mockups/` ให้ดูเป็น roadmap

## จุดที่หน้าจอยังไม่เหมาะกับทีมขาย

ข้อความสำหรับนักพัฒนาในคอลัมน์ขวาของ Workspace แก้แล้วใน #922 ที่ยังเหลือ:

- หน้าประวัติแสดงรหัส Interaction แบบ UUID และ breadcrumb เป็น "คุณภาพและกำกับ"
- เมนูหน้าแรกของ Console บางรายการมีคำอธิบายกว้าง ๆ ว่า "เปิดพื้นที่ทำงานนี้"
- แผงลูกค้าใน Workspace ยังไม่จัดระยะและลำดับปุ่ม
- ระหว่างเชื่อมลูกค้า API อาจตอบ `RESOURCE_BUSY` ชั่วคราว หน้าจอลองใหม่เองโดยไม่แสดง error
  (เจอในรอบซ้อมบน `main` 19 พ.ย. 2569)
