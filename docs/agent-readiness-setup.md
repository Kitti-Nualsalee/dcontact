> Mockup: [`mockups/agent-readiness-setup.html`](../mockups/agent-readiness-setup.html) (ปุ่มสถานการณ์จำลองด้านบน)

## คำตัดสินของ owner (20 พ.ย. 2569)

1. หลัง login Agent **เลือกสถานะก่อน** แล้วจึงเข้า Workspace
2. การทดสอบอุปกรณ์เป็น **ปุ่มแยกที่มุมซ้ายล่าง** และ **ไม่บังคับ**
3. สถานะมี **Ready, Not Ready และอื่น ๆ** — ออกแบบเป็น Ready / Not Ready พร้อมเหตุผล / Offline
   และสถานะที่ระบบตั้งให้เอง (ดูหัวข้อโมเดลสถานะ)
4. **รายการเหตุผล Not Ready ให้ Admin ของ tenant แก้ได้ใน Console** โดยเริ่มจาก 7 ข้อตั้งต้น
5. **Not Ready ยังถือโทรศัพท์ไว้** (SIP register ค้าง) เพื่อกลับเป็น Ready ได้ทันที — Offline เท่านั้นที่ปล่อยโทรศัพท์
6. **ค่าเริ่มต้นบนหน้าเลือกสถานะ = สถานะล่าสุดที่ Agent เลือก** (จำในเครื่อง) ครั้งแรกเป็น Ready
7. **ทดสอบเครือข่ายไว้รอบถัดไป** — รอบแรกปุ่มทดสอบมีแค่ไมค์และลำโพง
8. **ยังไม่เก็บผลทดสอบอุปกรณ์ที่ server** — ผลและชื่ออุปกรณ์อยู่ใน browser ของ Agent เท่านั้น

## โมเดลสถานะ

| ที่ Agent เห็น | ใครตั้ง | agent state | รับสาย | หมายเหตุ |
| -------------- | ------- | ----------- | ------ | -------- |
| **Ready** · พร้อมรับสาย | Agent | `AVAILABLE` | ✓ | ต้องผ่านขั้นเตรียมรับสาย |
| **Not Ready** · <เหตุผล> | Agent / Supervisor | `BREAK` + `reasonCode` | ✗ | ต้องเลือกเหตุผลทุกครั้ง · ถือโทรศัพท์ที่เชื่อมไว้แล้วต่อ |
| **Offline** · ออฟไลน์ | Agent / ระบบ | `OFFLINE` | ✗ | ไม่ขอไมค์ ไม่ register SIP |
| กำลังเสนอสาย | ระบบ | `RESERVED` | — | เปลี่ยนเองไม่ได้ |
| อยู่ในสาย | ระบบ | `BUSY` | — | เลือก "หลังจบงาน" ล่วงหน้าได้ |
| After-call work · สรุปผลหลังสาย | ระบบ | `ACW` | — | เลือก "หลังจบงาน" ล่วงหน้าได้ |
| Not Ready · ไม่ได้รับสายที่เสนอ | ระบบ | `BREAK` (cooldown) | ✗ | พฤติกรรม `COOLDOWN_REQUEUE` เดิมของ router |

เหตุผลเริ่มต้นของ Not Ready: พักสั้น (Break), พักเที่ยง (Lunch), ประชุม (Meeting), อบรม (Training),
โค้ช/ประเมิน (Coaching), งานหลังบ้าน (Back office), ธุระส่วนตัว (Personal) — ใส่ให้ทุก tenant ตอนสร้าง
Admin แก้ได้ที่ Console (ตัดสินแล้ว ดูหัวข้อรายการเหตุผล)

- **หลังจบงาน**: ระหว่าง `BUSY`/`ACW` ตัวเลือกสถานะแสดงสถานะระบบพร้อมเวลา และมีช่อง "หลังจบงาน"
  (ค่าเริ่มต้น Ready) เมื่อบันทึกสรุปผลแล้วระบบเปลี่ยนเป็นสถานะนั้น — เช่น ขอพักเที่ยงต่อจากสายนี้
- **เวลาในสถานะ** แสดงข้างตัวเลือกเสมอ (เช่น Not Ready · ประชุม 12:04)
- **Supervisor เปลี่ยนสถานะให้** (`supervisor-live-api.ts` มีอยู่แล้ว): แถบแจ้งชื่อหัวหน้า เวลา และเหตุผล
  พร้อมปุ่มรับทราบ ไม่ใช้ modal
- Offline กับ Not Ready ต่างกันที่ Offline ปล่อยโทรศัพท์ (unregister SIP และหยุดใช้ไมค์) ส่วน Not Ready
  ถือโทรศัพท์ที่เชื่อมไว้แล้วต่อ เปลี่ยนกลับเป็น Ready ได้ทันทีโดยไม่ต้อง register ใหม่ (ตัดสินแล้ว ข้อ 5)
- Not Ready ที่ยังไม่เคยเชื่อมโทรศัพท์ (เลือกตอน login หรือเข้าแบบ Not Ready เพราะเตรียมล้มเหลว)
  จะเตรียมรับสายครั้งแรกเมื่อเปลี่ยนเป็น Ready

## Flow

```
Login (OIDC) ─▶ มีงานในมือไหม? ──ใช่──▶ Workspace ทันที (ไม่ถามสถานะ) + แถบบอกว่ามีสายค้าง
                     │ ไม่
                     ▼
              หน้าเลือกสถานะ
               ├─ Ready ───────────▶ เตรียมรับสายอัตโนมัติ ──สำเร็จ──▶ Workspace (AVAILABLE)
               │                                          └─ล้มเหลว─▶ บอกเหตุ + [ลองอีกครั้ง] / [เข้าแบบ Not Ready]
               ├─ Not Ready + เหตุผล ─▶ Workspace (BREAK + reasonCode)
               └─ Offline ─────────▶ Workspace (OFFLINE)

ปุ่ม "ทดสอบอุปกรณ์" มุมซ้ายล่าง ── เปิดได้ทั้งบนหน้าเลือกสถานะและใน Workspace (ไม่บังคับ)
```

"งานในมือ" ใช้นิยามเดิมของ `workInHand` รวม offer ที่ค้าง — หลักการ UI ข้อ 4 ห้ามขวางงานสด

## หน้าเลือกสถานะ

- การ์ดกลางจอ ทักชื่อ Agent และตัวเลือกแบบ radio card สามแบบ (Ready / Not Ready / Offline)
  เลือก Not Ready แล้วเหตุผลขึ้นเป็นปุ่มเลือกในการ์ดเดียวกัน ปุ่มเข้ากดได้เมื่อเลือกเหตุผลแล้ว
  ปุ่มหลักเดียว **เข้า Workspace**
- ค่าเริ่มต้น: สถานะล่าสุดที่ Agent เลือก (จำใน `localStorage`) ครั้งแรกเป็น **Ready** (ตัดสินแล้ว ข้อ 6)
- เลือก **Ready** แล้วกดเข้า → ระบบเตรียมเท่าที่จำเป็นต่อการรับสาย แสดงเป็นรายการสั้นใต้ตัวเลือก
  ไม่ใช่การทดสอบอุปกรณ์:
  1. ตั้งหน้านี้เป็นจุดรับงาน (work-session lease) — ถ้าอีกแท็บถืออยู่ ถามย้ายด้วย `takeover` เดิม
  2. ขอใช้ไมโครโฟน (`getUserMedia` ด้วยอุปกรณ์ที่เลือกไว้)
  3. เชื่อมระบบโทรศัพท์ (SIP register → dphone `READY`)
  4. เรียก `becomeAvailable` แล้วเข้า Workspace
- ล้มเหลวขั้นใด: หยุด บอกเหตุเป็นภาษาคนและวิธีแก้ ให้เลือก **ลองอีกครั้ง** หรือ **เข้าแบบ Not Ready · งานหลังบ้าน**
  (เช่น ไมค์ไม่ได้รับอนุญาต → วิธีเปิดสิทธิ์; SIP ล้ม → รหัสสั้นและเวลาให้แจ้งผู้ดูแล ไม่แสดง credential)
- เลือก **Not Ready** หรือ **Offline**: เข้า Workspace ทันที ไม่ขอไมค์และไม่ register SIP จนกว่าจะเปลี่ยนเป็น Ready
  (หลังเชื่อมแล้ว การเปลี่ยนเป็น Not Ready ไม่ปล่อยโทรศัพท์ มีแค่ Offline ที่ปล่อย)

## ใน Workspace

- ตัวเลือกสถานะอยู่มุมขวาบนของหัว Workspace (แทนชิปสถานะหลายอันเดิม): Ready, กลุ่ม Not Ready
  ตามเหตุผล และ Offline พร้อมเวลาในสถานะ เปลี่ยนเป็น **Ready** ใช้ขั้นเตรียมรับสายชุดเดียวกับหน้าเลือกสถานะ
  ระหว่างมีงานแสดงสถานะระบบและช่อง "หลังจบงาน" (ดูโมเดลสถานะ)
- **ไมค์หลุดกลางกะ**: ระบบเปลี่ยนเป็น Offline ตามพฤติกรรมเดิม แถบสีแดงบอกอุปกรณ์ที่หลุดพร้อมปุ่ม
  **กลับเป็น Ready** และชี้ไปที่ปุ่มทดสอบอุปกรณ์
- **reload ระหว่างสาย**: ข้ามหน้าเลือกสถานะ สายเดิมอยู่ต่อที่ dphone
- แท็บ **ความพร้อม** ในแผงขวาของ V3 ไม่ต้องมีแผงตรวจอุปกรณ์/เปิดรับสายแล้ว (ย้ายไปตัวเลือกสถานะและปุ่มทดสอบ)
  เหลือข้อมูลสถานะของระบบเท่านั้น

## รายการเหตุผล Not Ready (Console)

- หน้าตั้งค่าใน Console สำหรับ Admin ของ tenant: เพิ่ม, เปลี่ยนชื่อ (TH/EN), เปิด/ปิด และลากเรียงลำดับ
- เหตุผลที่เคยถูกใช้แล้ว **ลบไม่ได้ ปิดได้เท่านั้น** เพื่อให้ประวัติสถานะและรายงานย้อนหลังยังอ่านชื่อเหตุผลได้
- ต้องเปิดอยู่อย่างน้อย 1 เหตุผล (ไม่งั้น Agent เลือก Not Ready ไม่ได้)
- เหตุผลที่ปิดแล้วหายจากตัวเลือกของ Agent ทันที Agent ที่อยู่ในเหตุผลนั้นอยู่แล้วคงสถานะเดิมจนกว่าจะเปลี่ยนเอง
- server ตรวจว่า `reasonCode` เป็นของ tenant และยังเปิดอยู่ทุกครั้งที่ตั้งสถานะ
- สิทธิ์แก้ใช้ capability ของ Core Settings ที่มีอยู่ (ไม่สร้างบทบาทใหม่) — ต้องตรวจชื่อ capability ตอน implement

## ปุ่มทดสอบอุปกรณ์ (มุมซ้ายล่าง)

- ปุ่มติดมุมซ้ายล่างของพื้นที่เนื้อหา (ถัดจาก rail) บนทุกหน้า แสดงผลทดสอบล่าสุด: "ยังไม่เคยทดสอบ",
  "ผ่าน · เมื่อวาน 08:59" หรือ "มีข้อควรตรวจ" พร้อมจุดสี + ข้อความ (ไม่ใช้สีอย่างเดียว)
- กดแล้วเปิด **แผงลอยเหนือปุ่ม** ไม่ใช่ modal เต็มจอ ปิดด้วยปุ่มปิด, กดปุ่มเดิม หรือ Esc
- ระหว่างอยู่ในสาย ปุ่มกดไม่ได้และบอกว่า "ทดสอบได้หลังจบสาย" (ไมค์กำลังใช้คุยกับลูกค้า)
- ตำแหน่งทับ dphone ลอยไม่ได้: dphone อยู่ขวาล่าง ปุ่มนี้อยู่ซ้ายล่าง

| รายการ | ทำอะไร | State |
| ------ | ------ | ----- |
| ไมโครโฟน | เลือกอุปกรณ์, แถบระดับเสียงสด, ผ่านเมื่อได้ยินเสียงพูด ~1 วินาที, อัด 3 วินาทีฟังกลับ (ไม่เก็บไฟล์) | กำลังฟัง, ไม่ได้ยินเสียง 8 วินาที, ไม่อนุญาต, ไม่พบอุปกรณ์, ถูกแอปอื่นใช้, ผ่าน |
| ลำโพงหรือหูฟัง | เลือกอุปกรณ์ (`setSinkId`), เล่นเสียงเรียกเข้าจริง, ถามได้ยิน/ไม่ได้ยิน | รอ, รอตอบ, ไม่ได้ยิน, browser เลือกไม่ได้, ผ่าน |
| คุณภาพเครือข่ายเสียง | กดเริ่มเอง ~5 วินาที แสดง RTT และ % เสียงหาย | ยังไม่ตรวจ, ดี, ช้า — **รอบถัดไป** (ตัดสินแล้ว ข้อ 7) |

ทุกรายการทดสอบแยกกันได้ ไม่ต้องทำครบ อุปกรณ์ที่เลือกในแผงนี้เป็นตัวที่สายถัดไปใช้

## ข้อกำหนดทางเทคนิค

- **ห้าม remount** (ADR-026): หน้าเลือกสถานะเป็น view หนึ่งของ `AgentWorkspace` ไม่ใช่ route/component แยก
  dphone, `<audio>` และ lease สร้างครั้งเดียวและใช้ต่อใน Workspace
- **อุปกรณ์ที่เลือกต้องเป็นตัวที่ใช้ในสายจริง**: ปัจจุบันสายใช้ `constraints: { audio: true }` ใน
  `sip-js-transport.ts` และไม่เลือกลำโพง ต้องส่ง `deviceId` เข้า constraints และเรียก `setSinkId` กับ
  `remoteAudio`/เสียงเรียกเข้า; อุปกรณ์ที่จำไว้หายไป → ใช้ค่าเริ่มต้นและบอก Agent
- แถบระดับเสียงใช้ `AudioContext` + `AnalyserNode` เฉพาะตอนแผงเปิด ปิดเมื่อปิดแผง
- ผลทดสอบและชื่ออุปกรณ์อยู่ใน browser เท่านั้น ไม่ส่งขึ้น server (ชื่ออุปกรณ์อาจมีชื่อคน) (ตัดสินแล้ว ข้อ 8)
- **งานฝั่ง server สำหรับ Not Ready/Offline**: router และ Supervisor รู้จัก `BREAK` แล้ว
  (`supervisor-live-api.ts` บังคับได้พร้อม `reason` แบบข้อความอิสระ, router ใช้เป็น cooldown)
  แต่ยังไม่มี:
  - API ของ Agent ให้ตั้ง `BREAK` + `reasonCode` และ `OFFLINE` เอง (`/workspace/agent/availability` รับเฉพาะ `AVAILABLE`)
  - รายการเหตุผล (reason code catalog) ต่อ tenant และ `reasonCode` ใน state/event ให้ Supervisor และรายงานใช้
  - สถานะ "หลังจบงาน" ที่ server ใช้ตอนปิด ACW (ถ้าเก็บแค่ฝั่ง browser จะหายเมื่อ reload)
  - snapshot ต้องคืน `stateSince` เพื่อแสดงเวลาในสถานะ และคืนผู้เปลี่ยนเมื่อ Supervisor บังคับ
- ข้อความผ่าน catalog `workspace` ทั้ง TH/EN, token และ component จาก `@d-contact/ui-react`
- โหมด `chrome-extension`: ขั้นเตรียมรับสายใช้ "เชื่อม D-Phone extension" แทนการขอไมค์ และปุ่มทดสอบ
  เปิดการทดสอบใน extension; โหมด `external-simulator` ไม่ขอไมค์และซ่อนปุ่มทดสอบ; `embedded` ไม่ใช้หน้านี้

## นอกขอบเขตรอบนี้

- รายงานเวลาในแต่ละสถานะ/เหตุผล (ข้อมูลพร้อมเมื่อมี `reasonCode` ใน event แล้ว)
- Supervisor เห็นผลทดสอบอุปกรณ์ของ Agent
