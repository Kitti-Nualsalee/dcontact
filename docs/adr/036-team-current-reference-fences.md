# ADR 036: ปิด Team ด้วย current-reference closure และ transaction fences ในฐานข้อมูล

- **สถานะ:** Accepted ตาม [Phase Contract #723 §7](https://github.com/Kitti-Nualsalee/dcontact/issues/723) และ [ข้อยุติ #724](https://github.com/Kitti-Nualsalee/dcontact/issues/724#issuecomment-6261994693); การบังคับใช้และหลักฐาน completion อยู่ใน [#727](https://github.com/Kitti-Nualsalee/dcontact/issues/727)

Team มีทั้ง foreign keys และ logical references ใน IAM, Contact Governance, Journey และ Outbound การเปลี่ยน `is_active` ไม่ขัดกับ FK KEY SHARE จึงใช้เพียง FK หรือการตรวจใน Core HTTP ไม่พอ Process lock ก็ไม่ครอบ repository/worker หลายตัว เลือก PostgreSQL transaction advisory locks โดย writer ถือ tenant shared fence และ Team shared fences ของ old/new UUID ตามลำดับ ส่วน deactivate ถือ tenant exclusive fence แล้ว Team exclusive fence ใช้ try-lock เพื่อให้ writer ที่ถือ domain row lock มาก่อน rollback ได้ทันทีเมื่อชน ไม่เพิ่มวงจรรอข้าม context และไม่ถือ fence ตลอดอายุสายหรืองาน

Current reference หมายถึงสิทธิ์/ownership/งานที่ยังทำต่อได้ตาม predicates ในสเปก ไม่ใช่ทุกแถวที่มี UUID ทีม Future delegation ยังเป็น potential claim ส่วน immutable history หรือ terminal ledger ไม่บล็อกเพียงมีชื่อทีม Runtime อ้าง pinned definition ตามเวอร์ชันที่ใช้จริง ไม่อ่าน current head แทน บทบาทของ `NULL` ที่เป็น unscoped ตาม schema แยกจาก binding ที่ขาดหรือขัดกัน ตรวจ structured owner command ตาม J2 contractVersion และ owner canonical records ไม่ใช้ JSON text search เมื่อยังพิสูจน์ทีมของ current work ไม่ได้ให้หยุดเฉพาะการปิดทีมใน tenant นั้น ไม่สร้าง manual binding, force option หรือยกเลิกงานแทนเจ้าของ domain

Advisory lock เป็น reentrant ภายใน transaction เดียว จึงต้องมี deferred constraints ตรวจ final state อีกชั้น รวม insert→deactivate และ deactivate→insert การเพิ่มแล้วถอน reference จน final state ปลอดภัยไม่เป็น blocker ถาวร Helper ที่อ่านหลัง lock เป็น VOLATILE และออก SQL statement ใหม่ใน READ COMMITTED ไม่อาศัย snapshot ก่อน lock การเปลี่ยนชื่อไม่เข้า reference fence; cleanup/settlement/revocation/move-out ตรวจเฉพาะ claim ที่เพิ่ม ไม่บังคับ active กับทีมเก่าที่กำลังถอน reference

ค่าที่เลือกมีต้นทุนคือทุก material writer ต้องร่วม protocol และ closure query ต้องอยู่ใน budget ของ deactivate จึงเก็บ inventory ของตาราง/predicate/entry point/cleanup/constraint/test และให้ writer ใหม่เข้าผ่าน additive extension ก่อนเปิดใช้ ไม่กำหนด People ที่ยังไม่ merge เป็น dependency แต่ต้องครอบตาราง People ที่มีจริงแล้วใน baseline การอัปเกรด schema/contract ต้องทดสอบ writers จริงทั้งสองลำดับ ไม่อ้าง fixture SQL หรือ prototype เป็นหลักฐานแทน runtime

Prisma รุ่นที่ pin อาจคืนผลจาก callback แม้ deferred constraint ทำให้ COMMIT rollback เส้นทาง tenant transaction กลางจึง force `SET CONSTRAINTS ALL IMMEDIATE` ก่อนคืนผล เช่นเดียวกับ Core command transaction เพื่อให้ผู้เรียกเห็น failure และไม่ส่ง success จากงานที่ไม่ commit ไม่เปลี่ยน ownership ของ domain transaction หรือขยาย timeout โดยปริยาย

Baseline final-state เก็บใน `dc_team_reference_checks` แบบ transaction-local rows ที่ trigger เป็นผู้เขียนเท่านั้น ใช้ opaque binding references และ state hints ไม่มี User/email/password/token หรือ draft payload ป้องกันการคำนวณ OLD claims ผ่าน canonical parent ที่ถูกแก้ไปแล้ว ข้อมูลนี้ลบเมื่อ deferred check ผ่าน และ rollback พร้อม transaction ไม่ใช่ durable projection/authority ใหม่ การลบ suppressing proof ต้องถือ canonical affected Team locks ด้วย แม้ก่อนลบ predicate ยังไม่ current

Platform bootstrap ใช้ข้อยกเว้นเดิมเฉพาะ database principal ที่เป็นสมาชิก provisioner และ tenant ยัง PROVISIONING พร้อม row lock กัน activation ไม่ยืม lifecycle อย่างเดียวเป็น authority ของ app และไม่เปิด bypass บน ACTIVE tenant การปิด Team ตรวจ closure ครั้งเดียวใน final guard; hot predicates อ่าน direct columns เพื่อลดต้นทุน มี budget test ทั้ง EXPLAIN และ commit บน 60,000 references

รายละเอียด canonical sources, current writers, cleanup, indexes และ evidence discovery อยู่ที่ [Team reference inventory](../core-settings/team-reference-inventory.md) การเพิ่ม writer จาก People หรือ context อื่นต้องขยาย coordination และหลักฐานก่อนเปิดใช้ ไม่มีการเพิ่ม owner decision/authority จากรายการ inventory เอง
