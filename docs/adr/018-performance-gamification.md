# ADR 018: Performance Management & Gamification — scorecard เป็นชั้นรวมของโมดูลอื่น ไม่ใช่แหล่งข้อมูลใหม่

- **สถานะ:** Accepted
- **วันที่:** 2026-08-08

## บริบท

ตอนนี้ตัวเลขของ agent กระจายอยู่ 4 ที่: คะแนน QM, adherence จาก WFM, AHT/ปริมาณจาก interaction,
CSAT จาก feedback — หัวหน้าทีมต้องเปิด 4 หน้าจอเพื่อคุยกับลูกทีมหนึ่งคน
คู่แข่งขายรวมเป็น "Performance Management" (NICE) หรือผูกกับ WEM (Zoom)

## การตัดสินใจ

1. **Performance ไม่มีข้อมูลของตัวเอง — มีแต่ *นิยาม* และ *ผลรวม***
   `pm_metrics` เป็นสูตรที่ชี้ไปยังแหล่งเดิม (qm/wfm/interactions/feedback/cases)
   ห้ามคัดลอกข้อมูลดิบมาเก็บซ้ำ เพราะวันที่ตัวเลขสองที่ไม่ตรงกันคือวันที่โมดูลนี้ตาย

2. **Scorecard เป็น metadata ต่อ tenant — น้ำหนักและเป้าหมายลูกค้าตั้งเอง**
   ตาม [ADR-005](005-multitenant-metadata-architecture.md); เราให้ template มาตรฐานมา 3 ชุด
   (service / sales / collection) แล้วให้แก้ต่อ

3. **Gamification เป็นชั้นบนของ scorecard และ *ปิดได้* — ค่าเริ่มต้นคือปิด**
   วัฒนธรรมองค์กรไทยหลายแห่งไม่รับ leaderboard สาธารณะ และการเปิดโดยไม่ถามคือการทำร้ายทีม
   เปิดแล้วต้องเลือกได้ว่าแสดงชื่อจริงหรือแสดงเฉพาะอันดับของตัวเอง

4. **ห้ามให้ metric ที่ผลักพฤติกรรมผิดอยู่ในกระดานคะแนนเดี่ยว ๆ**
   AHT ต้องมาคู่กับ CSAT หรือ FCR เสมอ (บังคับในระดับ validation ของ scorecard) —
   ระบบที่ให้รางวัลคนคุยสั้นจะได้คนวางสายเก่ง ซึ่งเป็นความเสียหายที่ตรวจไม่เจอในตัวเลข

5. **คะแนนต้องมีขนาดตัวอย่างขั้นต่ำก่อนแสดง**
   agent ที่ถูกตรวจ 1 สายในเดือนนี้ห้ามมีอันดับ — เกณฑ์ขั้นต่ำเป็น config และมีค่าเริ่มต้นที่ไม่เป็นศูนย์

6. **1:1 / coaching ใช้ของที่ QM มีอยู่แล้ว ไม่สร้างใหม่**
   `qm_coaching` + ปฏิทิน WFM ([ADR-010](010-quality-management.md) §12) — performance แค่เป็น
   จุดตั้งต้นที่กด "เปิดการโค้ช" จากตัวเลขที่เห็น

7. **acceptance rate ของ agent assist ห้ามเข้ากระดานคะแนน**
   ([ADR-014](014-agent-assist.md) ข้อ 6) — เป็นสัญญาณคุณภาพของฟีเจอร์ ไม่ใช่ของคน

## ผลที่ตามมา

- `apps/api` ได้ metric registry + งานสรุปรายวัน (`pm_scores` ต่อ agent ต่อวัน)
- ไม่มี service ใหม่ ไม่มีตารางข้อมูลดิบใหม่
- entitlement: `modules.performance.{enabled, scorecards, gamification, goals}`
- ต้องมีการทดสอบว่า "ตัวเลขบน scorecard = ตัวเลขบนหน้าโมดูลต้นทาง" เป็น CI check ถาวร

## ทางเลือกที่ไม่เอา

| ทางเลือก | เหตุผลที่ไม่เอา |
|---|---|
| คัดลอกข้อมูลดิบมาไว้ในตาราง performance | ตัวเลขสองแหล่งไม่ตรงกัน = โมดูลนี้ถูกเลิกใช้ |
| เปิด gamification เป็นค่าเริ่มต้น | ทำร้ายทีมในองค์กรที่ไม่ได้เตรียมวัฒนธรรมไว้ |
| ให้ AHT เป็น metric เดี่ยวบนกระดาน | ผลักพฤติกรรมวางสายเร็ว |
| สร้างระบบโค้ชใหม่ | ซ้ำกับ `qm_coaching` ที่เชื่อมปฏิทิน WFM อยู่แล้ว |
