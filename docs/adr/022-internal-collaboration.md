# ADR 022: Internal Collaboration — แชทภายในเป็นเครื่องมือของ "งานตรงหน้า" ไม่ใช่ Teams ฉบับของเรา

- **สถานะ:** Accepted
- **วันที่:** 2026-08-09

## บริบท

เอเจนต์กับหัวหน้าต้องคุยกันตลอดเวลาที่ทำงาน — ถามเรื่องเคส ขอความช่วยเหลือกลางสาย ส่งภาพหน้าจอ
ส่งเอกสารให้ดู วันนี้ทีมส่วนใหญ่ใช้ LINE กลุ่มหรือเดินไปคุย ซึ่งแปลว่า **สิ่งที่คุยกันไม่เคยกลับเข้าระบบ**
และไม่มีใครรู้ว่าเอเจนต์ติดอะไรบ่อยที่สุด

Zoom ได้เปรียบเพราะมี Zoom Workplace อยู่แล้ว — agent คุยกับคนทั้งบริษัทได้ฟรี เราไม่มีฐานนั้น
การไล่ทำแชททั่วไปให้ครบเท่า Teams/Slack คือการใช้เวลาหนึ่งปีเพื่อได้ของที่แพ้ในทุกมิติ

## การตัดสินใจ

1. **แชทภายใน "ไม่ใช่" interaction — ห้ามเข้า router ห้ามกิน capacity ห้ามนับใน AHT/SLA/occupancy**
   เส้นเดียวกับที่ [ADR-016](016-case-management.md) วางไว้ว่าเคสไม่ใช่ interaction
   ถ้าเบลอเมื่อไหร่ ตัวเลข SLA ทั้งระบบจะโกหก และไม่มีใครกล้าใช้รายงานอีกเลย
   (`ic_*` ไม่มีคอลัมน์ไหนไหลเข้า `interactions` — ยกเว้น `ic_consult` ที่ผูกด้วย FK อย่างเดียว)

2. **presence มีแหล่งเดียว = สถานะเอเจนต์จาก router**
   แชทเป็นผู้*อ่าน* สถานะ ไม่ใช่เจ้าของ — ระบบ presence ที่สองจะเพี้ยนกับของจริงภายในสัปดาห์แรก
   และหัวหน้าจะไม่รู้ว่าควรเชื่ออันไหน

3. **สิ่งที่ทำให้โมดูลนี้มีค่าคือ Consult ที่ผูกกับ interaction ไม่ใช่ตัวแชท**
   "ถามผู้เชี่ยวชาญระหว่างคุยกับลูกค้า" ต้องเห็นบริบทครบ (ลูกค้าคือใคร เรื่องอะไร คุยถึงไหน)
   แล้วบันทึกกลับเข้า interaction เมื่อจบ — ทุกครั้งที่ต้องถาม **คือหลักฐานว่าคลังความรู้ขาดอะไร**
   จึงป้อนเข้า `kb_gap` ([ADR-013](013-virtual-agent-knowledge.md)) อัตโนมัติ

4. **ไฟล์แนบอยู่ใน v1 — รูปและเอกสาร แต่มีขอบเขตชัด**
   นี่คือความต้องการจริงของหน้างาน (ส่งภาพหน้าจอ error, สลิป, ใบเสร็จ, เอกสารเงื่อนไข)
   แต่ **ไฟล์ที่พนักงานส่งกันมีข้อมูลลูกค้าเสมอ** จึงต้องมาพร้อมกติกาตั้งแต่วันแรก ไม่ใช่เติมทีหลัง:
   ชนิดที่อนุญาต · เพดานขนาด · สแกนก่อนดาวน์โหลดได้ · signed URL อายุสั้น · retention · audit ทุกการเปิด
   (รายละเอียดใน [internal-collaboration §6](../internal-collaboration.md))

5. **ข้อความ/ไฟล์ที่ผูกกับ interaction หรือเคส = หลักฐาน อยู่ใต้ retention ของสิ่งนั้น**
   ไม่ใช่ retention ของแชท — เพราะเวลามีข้อพิพาท คนถามหาคือ "ตอนนั้นทีมคุยอะไรกันเรื่องสายนี้"
   ส่วนแชททั่วไปมีอายุของตัวเอง (ค่าเริ่มต้น 180 วัน) และการค้นข้ามห้องเป็นสิทธิ์แยกที่ถูก audit

6. **การแจ้งเตือนต้องยอมแพ้ให้งานตรงหน้า**
   เอเจนต์ที่กำลังคุยกับลูกค้าได้แจ้งเตือนแบบเงียบเป็นค่าเริ่มต้น (นับ unread ไม่เด้ง)
   หัวหน้าส่งแบบด่วนได้ แต่ต้องกดเลือกและถูกบันทึก — ระบบที่เด้งใส่หน้าเอเจนต์ตอนลูกค้าพูดอยู่
   คือระบบที่ทำให้บริการแย่ลงโดยที่ตัวเลขไม่ฟ้อง

7. **สิ่งที่ตั้งใจไม่ทำใน v1** — วิดีโอคอล/ประชุม (แปะลิงก์ Zoom/Teams แทน) · เธรดซ้อน ·
   แชทกับลูกค้า (นั่นคือ `apps/channels`) · ไฟล์วิดีโอ/ไฟล์ขนาดใหญ่ · แอปมือถือ
   รายการนี้เป็นส่วนหนึ่งของ ADR ไม่ใช่ความเข้าใจร่วม — ถ้าจะเพิ่มต้องแก้ ADR

8. **บ้านของโค้ด: `apps/api` ก่อน แต่ตาราง `ic_*` แยกตั้งแต่แรก**
   ปริมาณงานยังไม่คุ้มกับ service ใหม่ (แพตเทิร์นเดียวกับ `fb_*` ใน `apps/qm`) —
   WS ใช้ gateway เดิม, fan-out ผ่าน topic ใหม่ `dc.collab.events` ซึ่งได้ analytics
   และสะพานไป Teams/Slack (เฟส CL5) มาฟรี

## ผลที่ตามมา

- topic ใหม่ `dc.collab.events` (`message.sent` / `consult.opened` / `consult.answered` / `file.uploaded`)
- bucket ใหม่ใน MinIO/S3 แยกจากไฟล์เสียง: `collab/{tenantId}/…` (ต่างจาก `recordings/` เพราะคนละ retention คนละสิทธิ์)
- ต้องมี virus scanner ในสถาปัตยกรรม (ClamAV เป็น sidecar) — ของใหม่ชิ้นเดียวที่โมดูลนี้พาเข้ามา
- entitlement: `modules.collab.{enabled, channels, consult, expertRouting, attachments, compliance, bridge}`
  + quota `collabStorageGb`
- [ADR-014](014-agent-assist.md) ข้อ 5 ยังใช้: ผู้ช่วย AI เสนอข้อความได้ แต่คนกดส่ง — รวมถึงในแชทภายใน

## ทางเลือกที่ไม่เอา

| ทางเลือก | เหตุผลที่ไม่เอา |
|---|---|
| ทำแชทเต็มรูปแข่ง Teams/Slack | 6–9 เดือนเพื่อของที่แพ้ในทุกมิติ และไม่ได้แก้ปัญหาที่ลูกค้าจ่ายเงินให้เราแก้ |
| ต่อ Teams/Slack อย่างเดียว ไม่มีแชทในแอป | เอเจนต์ที่กำลังคุยสายต้องสลับหน้าจอ (adherence พัง) + ลูกค้า on-prem หลายรายไม่มี Teams + ผูกกับ interaction ไม่ได้ |
| ให้แชทเป็น work item ที่ router กระจาย | ตัวเลข capacity/SLA เสียทันที และเอเจนต์จะพลาดสายเพราะเพื่อนทัก |
| ไม่มีไฟล์แนบ | ปฏิเสธความจริงของหน้างาน — คนจะไปส่งผ่าน LINE แทน ซึ่งแย่กว่าทุกทาง |
| ให้แนบไฟล์อะไรก็ได้ ขนาดเท่าไหร่ก็ได้ | กลายเป็นที่เก็บไฟล์ที่ไม่มีใครดูแล + ช่องทางมัลแวร์ + ค่าพื้นที่บานปลาย |
| ทำ presence ของตัวเอง | เพี้ยนกับสถานะจริงภายในสัปดาห์แรก |
