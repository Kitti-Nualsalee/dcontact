# D-Contact Sales Script: One Page

ใช้เป็น talk track สำหรับการคุยครั้งแรกหรือเริ่ม demo ปรับคำในวงเล็บตามบริบทลูกค้าได้

## 1. เปิดการสนทนา

“ขอใช้เวลาสั้น ๆ ทำความเข้าใจ workflow ของทีมก่อนนะครับ/ค่ะ เพราะ D-Contact ครอบคลุมหลายส่วน เราอยากเลือกดูเฉพาะสิ่งที่ช่วยแก้ปัญหาของทีมคุณจริง ๆ วันนี้อยากโฟกัสเรื่อง operation, quality, workforce, automation หรือ reporting เป็นหลักครับ/ค่ะ?”

## 2. คำถาม discovery

“ตอนนี้ลูกค้าติดต่อเข้ามาผ่านช่องทางใดบ้าง และมีปริมาณหรือช่วง peak ประมาณเท่าไรครับ/ค่ะ?”

“ตั้งแต่รับ interaction จนปิดเคส มีจุดใดที่ต้องส่งต่อหรือทำข้อมูลซ้ำมากที่สุดครับ/ค่ะ?”

“ทีมวัดความสำเร็จด้วยตัวชี้วัดใด เช่น SLA, first response, QA score, adherence, conversion หรือ CSAT ครับ/ค่ะ?”

“รายงานปัจจุบันดึงจากระบบเดียวกันหรือยังต้องรวมข้อมูลด้วยมือครับ/ค่ะ?”

“ถ้าแก้ได้หนึ่งเรื่องใน 90 วันแรก เรื่องใดจะสร้างผลกระทบมากที่สุดครับ/ค่ะ?”

## 3. สะท้อนปัญหา

“จากที่ฟังมา ปัญหาหลักคือ [ปัญหา] ซึ่งกระทบ [ทีม/ลูกค้า/ตัวชี้วัด] และตอนนี้ติดที่ [ขั้นตอนหรือระบบเดิม] ถูกต้องไหมครับ/ค่ะ?”

## 4. นำเสนอคุณค่า

“สำหรับโจทย์นี้ เราแนะนำให้เริ่มจาก [use case] โดยเชื่อม [interaction/channel] เข้ากับ [case/routing/automation] แล้วติดตามผลผ่าน [quality/workforce/reporting] ทำให้ทีมเห็นเส้นทางตั้งแต่การติดต่อจนถึงผลลัพธ์ในบริบทเดียวกันครับ/ค่ะ”

## 5. Demo transition

“เดี๋ยวผม/ดิฉันจะแสดง 3 จุดที่เกี่ยวกับโจทย์นี้: มุมทำงานของ agent, การควบคุมของ supervisor และรายงานผลลัพธ์ ถ้าจุดใดไม่ตรงกับ workflow จริง ช่วยหยุดและบอกได้เลยครับ/ค่ะ”

## 6. รับมือข้อกังวลที่พบบ่อย

**มีระบบเดิมอยู่แล้ว**

“เข้าใจครับ/ค่ะ เราไม่จำเป็นต้องแทนที่ทุกระบบในครั้งเดียว เราสามารถเริ่มจาก workflow ที่มี pain point สูงสุด แล้วตรวจสอบ integration และขอบเขตข้อมูลก่อนตัดสินใจขยายครับ/ค่ะ”

**ต้องการ feature ที่ยังไม่เห็นใน demo**

“ขอแยกตรวจสอบให้ชัดว่าเรื่องนี้เป็น capability ที่มีอยู่, configuration, integration หรือ roadmap ครับ/ค่ะ ผม/ดิฉันจะบันทึก requirement และนัด technical validation เพื่อไม่ให้คำตอบคลาดเคลื่อน”

**ขอราคาเลย**

“ยินดีครับ/ค่ะ เพื่อให้ราคาเทียบกับ scope ได้จริง ขอทราบจำนวนผู้ใช้ ช่องทาง ปริมาณ interaction และ use case ระยะแรกก่อน จากนั้นเราจะสรุป option ที่เหมาะสมให้ครับ/ค่ะ”

**กังวลเรื่อง AI และข้อมูล**

“เราจะกำหนดขอบเขตการใช้ AI, knowledge, policy, human handoff และ audit ให้ชัดเจน พร้อมระบุข้อมูลที่ต้องใช้และสิทธิ์การเข้าถึงก่อนเริ่มครับ/ค่ะ”

## 7. ปิดการคุย

“วันนี้เราเห็นตรงกันว่า [pain point] และ use case แรกคือ [use case] โดยจะวัดจาก [success metric] ภายใน [ช่วงเวลา] ขั้นตอนถัดไปที่เหมาะสมคือ [workshop/pilot/technical validation] โดยมี [owner] และต้องเตรียม [ข้อมูลหรือระบบที่ต้องเชื่อม] ถูกต้องไหมครับ/ค่ะ?”
