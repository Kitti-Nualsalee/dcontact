# หลักการ UI/UX ของ D-Contact

เอกสารนี้เป็นเกณฑ์ที่ `ux-designer` ใช้ออกแบบ และ `ui-reviewer` ใช้ตรวจ PR
รายละเอียดค่าของ token อยู่ที่ [`packages/ui/README.md`](../packages/ui/README.md) และ component อยู่ที่
[`packages/ui-react/README.md`](../packages/ui-react/README.md) เอกสารนี้ไม่ทำซ้ำ แต่บอกว่าใช้อย่างไรให้ถูก

> **สถานะ: ร่าง** ข้อที่มีป้าย `[ต้องตัดสิน]` ยังเป็นสมมติฐานที่เจ้าของผลิตภัณฑ์ต้องยืนยัน

## ผู้ใช้และบริบท

| ผู้ใช้        | แอป                      | บริบท                                                         | สิ่งที่สำคัญที่สุด                     |
| ------------- | ------------------------ | ------------------------------------------------------------- | -------------------------------------- |
| เอเจนต์       | `apps/workspace`         | อยู่หน้าจอทั้งกะ คุยกับลูกค้าไปด้วย ใช้คีย์บอร์ดเป็นหลัก         | ความเร็ว, ไม่หลุดสาย, อ่านได้ในเสี้ยววินาที |
| Supervisor    | `apps/workspace`, wallboard | เฝ้าหลายคิวพร้อมกัน ต้องเห็นสิ่งผิดปกติทันที                   | severity ชัด, ข้อมูลหนาแน่น            |
| Admin ของ tenant | `apps/console`        | ตั้งค่านาน ๆ ครั้ง ต้องมั่นใจว่าไม่ทำพัง                        | ความชัดเจน, ยืนยันก่อนทำสิ่งที่ย้อนไม่ได้ |
| Platform operator | `apps/platform-console` | ดูแลหลาย tenant                                             | ไม่สับสนว่ากำลังอยู่ tenant ไหน        |

## หลักการ

1. **ความหนาแน่นสูงแต่อ่านง่าย** ใช้ density ตาม token (`--dc-row-table` 36px, `--dc-control-md` 32px)
   ไม่เพิ่มช่องว่างเพื่อให้ "ดูโปร่ง" ถ้าข้อมูลหายจากจอ
2. **คีย์บอร์ดก่อน** ทุก action หลักต้องทำได้ด้วยคีย์บอร์ด มี focus ring ที่มองเห็น ลำดับ tab ตามลำดับการอ่าน
3. **สีมีความหมายเดียว** severity กับ identity ห้ามปนกัน (ดู `packages/ui/README.md`) ห้ามใช้สีอย่างเดียวสื่อความหมาย
   ต้องมีข้อความหรือไอคอนกำกับ
4. **ห้ามรบกวนงานสด** หน้าที่ใช้ระหว่างสายห้าม remount, ห้าม modal ที่ขวางการคุย, ห้าม layout กระโดด
   เมื่อข้อมูลโหลดเสร็จ
5. **บอกผลของการกระทำเสมอ** action ที่สำเร็จแสดง toast, action ที่ล้มแสดงเหตุและทางแก้,
   action ที่ย้อนไม่ได้ต้องยืนยันด้วย `Dialog` ที่ระบุชื่อสิ่งที่จะได้รับผล
6. **ไทยก่อน อังกฤษต้องไม่พัง** ทุกหน้าต้องผ่านทั้ง TH และ EN ข้อความยาวต้องตัดหรือ wrap อย่างตั้งใจ
7. **ไม่เดาสิทธิ์ใน UI** สิ่งที่ผู้ใช้ทำไม่ได้มาจาก server; UI แสดงสถานะ "ไม่มีสิทธิ์" อย่างชัดเจน
   แทนการซ่อนเงียบ ๆ เมื่อผู้ใช้คาดว่าจะเห็น

## กติกาเชิงเทคนิค (ตรวจได้)

- ใช้ `var(--dc-*)` หรือ Tailwind preset `dc-` เท่านั้น ห้าม hex และห้าม palette เดิมของ Tailwind
- ระยะห่างอยู่ใน scale `--dc-space-1..10` ค่าที่ไม่ตรงให้ปัดเข้าขั้นที่ใกล้สุด
- ใช้ component จาก `@d-contact/ui-react` ก่อนเสมอ ถ้าไม่มีให้ระบุใน PR ว่าทำไมต้องสร้างใหม่
  และควรเข้า `ui-react` หรือไม่
- ข้อความทุกตัวมาจาก i18n catalog ห้าม hardcode ทั้งไทยและอังกฤษ
- ห้าม PII ใน URL
- contrast ผ่าน WCAG AA (ข้อความ 4.5:1, ส่วนประกอบ UI 3:1) ยกเว้นช่องว่างที่บันทึกไว้ใน `packages/ui/README.md`

## State ที่ทุกหน้าจอต้องออกแบบ

| State          | ต้องมี                                                    |
| -------------- | --------------------------------------------------------- |
| Loading        | skeleton ขนาดเท่าของจริง ไม่ทำให้ layout กระโดด           |
| Empty          | บอกว่าทำไมว่าง และ action ถัดไป (ถ้าผู้ใช้มีสิทธิ์)         |
| Error          | บอกสิ่งที่ล้มเป็นภาษาคน, ปุ่มลองใหม่, ไม่ทิ้งข้อมูลที่กรอกไว้ |
| ไม่มีสิทธิ์     | บอกว่าไม่มีสิทธิ์และติดต่อใคร                              |
| ข้อมูลยาว/เยอะ | ชื่อยาว 80 ตัวอักษร, ตาราง 500 แถว, ภาษาอังกฤษ            |
| Partial        | บางส่วนโหลดได้ บางส่วนล้ม                                  |

## Pattern

`[ต้องตัดสิน]` เลือกหน้าอ้างอิงที่ถือเป็นมาตรฐาน 2–3 หน้า แล้วใส่ไว้ที่นี่ ตัวเลือกจาก `mockups/`:

- ตาราง + filter: `[ต้องตัดสิน]`
- ฟอร์มตั้งค่า: `[ต้องตัดสิน]`
- หน้ารายละเอียด/โปรไฟล์: `[ต้องตัดสิน]`

กติกาชั่วคราวจนกว่าจะเลือก:

- **ตาราง** ใช้ `Table` ของ `ui-react`, หัวตารางติดบน, action ของแถวอยู่ท้ายแถว, filter อยู่เหนือตาราง
- **ฟอร์ม** label อยู่เหนือ input, error อยู่ใต้ field ที่ผิด, ปุ่มหลักหนึ่งปุ่มต่อฟอร์ม
- **หน้ารายละเอียด** ข้อมูลระบุตัวตนอยู่บนสุด, action หลักมองเห็นได้โดยไม่ต้องเลื่อน

## Viewport ที่ต้องตรวจ

| ขนาด     | ความกว้าง | ใช้กับ                                    |
| -------- | --------- | ----------------------------------------- |
| Desktop  | 1440px    | ทุกหน้า                                   |
| Laptop   | 1280px    | ทุกหน้า (จอเอเจนต์ส่วนใหญ่)                 |
| Tablet   | 768px     | `apps/console` `[ต้องตัดสิน]` ว่ารองรับหรือไม่ |

โหมดมืดยังอยู่นอกขอบเขต ไม่ต้องตรวจ
