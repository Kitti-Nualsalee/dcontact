## Coordination ที่ทุกแถวใช้ร่วมกัน

- `dc_team_reference_writer` เป็น BEFORE INSERT/UPDATE/DELETE ของตารางใน inventory ถือ tenant shared try-advisory fence ก่อน canonical lookup แล้วถือ old/new/canonical affected Team shared fences เรียง UUID; raw DML และ workers ที่ไม่ผ่าน Core API ยังถูกบังคับ ไม่เชื่อ cached `isActive`
- repository ที่ทราบทีมเรียก `lockTeamReferences` ก่อน domain row/fence เดิม ได้แก่ B1/B2, IAM scope/delegation, CG admission/alert, Dialer command admission, Journey definition/authoring/execution; writer ที่ resolve ทีมจาก domain rows ใช้ DB BEFORE trigger แบบ fail-fast เพื่อไม่รอ fence ขณะถือ domain row
- deactivate ถือ tenant exclusive แล้ว Team exclusive ก่อน Team row/CAS อ่าน current closure ใหม่ด้วย VOLATILE helpers ไม่มี network I/O ใน fence ชื่อ/defaults/rename ไม่เข้า reference fence
- `dc_team_reference_checks` เก็บ baseline claims ภายใน transaction ผ่าน trigger เท่านั้น เก็บ opaque resource references และ state hints ที่จำเป็น ไม่เก็บ User/email/password/token/raw request; app/PUBLIC ไม่มีสิทธิ์อ่านหรือเขียน; deferred `dc_team_reference_check_final` อ่าน final canonical state แล้วลบ baseline เมื่อผ่าน การ rollback ลบทั้ง unit
- `team_reference_final_state` ตรวจ closure ของ Team ที่ถูกปิดอีกครั้งเพื่อกัน reentrant advisory locks ใน transaction เดียว; `withTenantDatabaseTransaction` force constraints ก่อนคืน callback result ป้องกัน Prisma คืน success จาก COMMIT ที่ rollback
- การลบ proof ที่เคย suppress current work เช่น revocation, continuation, terminal segment head หรือ enrollment ต้องล็อก canonical Team candidates ด้วย แม้ก่อนลบยังไม่มี current claim; candidates ใช้ประสาน lock เท่านั้น ไม่เป็น blocker เพิ่ม
- active-check เฉพาะ claim ที่เพิ่ม/เปิดใหม่ หรือ User/Queue reactivation, publish/resume และ grant expiry extension ไม่บังคับ active old Team ของ cleanup/move-out การเปลี่ยนข้อมูลทั่วไปไม่เท่ากับ acquisition
- Core ใช้ lock timeout 250 ms, statement 2 s, transaction 5 s; busy rollback execution แต่คง admitted command ให้ตรวจ receipt/reconcile ID เดิม ไม่มี force/unassign/auto-cancel

## Canonical dependents และ unknown handling

- `jr_journey_definitions` เป็น immutable history และไม่บล็อกเอง แต่เปลี่ยน/ลบ pin ที่ live enrollment/SEND/owner/schedule/intent ใช้อยู่ต้องตรวจ dependents; `jr_segment_heads.terminal_entry_id` เป็นหลักฐาน suppress intent; enrollment ที่ผูก segment_intent_id/occurrence_id เป็น durable proof; baseline ใช้ค่า canonical ก่อน material write ไม่คำนวณ OLD ด้วย parent ที่ถูกเปลี่ยนแล้ว
- `cg_reservations` เปลี่ยน binding/status แล้วต้องตรวจ SEND dependents แม้ reservation ไม่มี current claim; `ob_dialer_command_inbox`, callbacks และ targets เปลี่ยน legacy owner fallback แล้วต้องตรวจ action/outbox dependents
- Structured payload ใช้ exact schema ของ contractVersion 1, action/command/hash/kind/enrollment/step/version bindings และ pinned source; ไม่ใช้ substring/JSON text search; invalid non-null payload/unsupported version ไม่ยืม legacy fallback
- Legacy null payload resolve จาก owner receipt ที่ผูก command/action/request hash และ positive record_version ที่ตรง canonical callback/target; no-outbox resolve จาก action+positive canonical receipts; conflicting/missing source/target/pin เป็น unresolved; ENSURE_CASE ไม่มี Team ใน Case canonical จึงไม่เดา target
- unfinished claim ที่ขาด/ขัด canonical binding หรือ Team อยู่ผิด tenant ให้ `UNRESOLVED_CURRENT_REFERENCE`; ปิดทุก Team ใน tenant นั้นไม่ได้ (`TEAM_REFERENCE_UNRESOLVED`) แต่ create/rename/org ไม่ติด unknown นี้; API ส่งเฉพาะชนิด+จำนวน ไม่มี PII/opaque ids

## ข้อมูลที่ไม่ใช่ blocker เพียงเพราะมี Team UUID

`jr_journey_definitions`/`jr_template_versions`, IAM grant/revocation/version/invalidation history, Core audit/receipt, metrics, `cg_decision_logs`, CG5 fact/transition history, terminal owner results/continuations และ terminal segment ledgers ไม่ใช่ current claim โดยลำพัง; `cg_callback_requests` ไม่มี Team owner column จึงไม่สร้าง predicate สมมติ; nullable unscoped Team ของ reservation/refilter ไม่เท่ากับ unresolved; live runtime ที่อ้าง history ยังตรวจตาม pin

`tenant_identity_reservations` และ `tenant_people_invitation_intents` เป็น B2 binding จริง ไม่ใช่ planned `TenantInvitation`; step receipts ที่จบแล้วไม่มี independent Team claim หาก People เปลี่ยน current writer/predicate ต้องเพิ่ม additive coordination + canonical binding + final constraints + races ก่อนเปิดใช้ โดยไม่เพิ่ม cross-team blocker อัตโนมัติ

## Coverage gate ก่อนปิด #727

Executable discovery ครอบ actual both-order cases ของ Template publish/lifecycle/fork/instantiate/upgrade, IAM grant/revoke และ authoring delegation/revoke, alert opening/ack/resolve/reopen, Dialer admit/schedule/cancel/supersede/originate/reconcile, Journey draft/publish/resume/transfer/clone/roll-forward, event/schedule/execution transitions, outcome/segment trigger, refilter/recovery/IAM invalidation, legacy processor, owner relay/reconcile/continuation และ governance effect relay ตามชื่อ `Core Team fence` ใน owner integration files นอกเหนือจาก DB/HTTP cases

`JourneySegmentRecovery.replayReceipt/skipQuarantine` เขียน receipt metadata ซึ่งไม่เป็น Team claim ตาม predicates; writer ที่สร้าง intent/refilter/enrollment ภายหลังถูกตรวจแยก ไม่ใช้ receipt READY เป็นหลักฐานว่าปลอดภัย Core authoring grant ที่ไม่มี application repository ใช้ operator-owned canonical DML ตาม authority เดิมและมี DB acquire/expiry-extension tests ไม่สร้าง grant UI/API ใหม่ในงานนี้
